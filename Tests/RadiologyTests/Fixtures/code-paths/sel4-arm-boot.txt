ARM power-on to root-task entry — seL4 d419a119a, AArch64 and AArch32 alternatives, conditional SMP/HYP/MCS paths
src/arch/arm/64/head.S:_start:AArch64 kernel entry. Power-on firmware and the ELF loader are outside this checkout; entry assumes loaded kernel/root-task images, zeroed BSS, and loader-provided MMU mappings. Receives root-image physical bounds, physical/virtual offset, user entry address, and DTB address/size in x0–x5.
src/arch/arm/32/head.S:_start:AArch32 alternative entry. Receives image arguments in r0–r3 and DTB arguments on the loader stack; selects supervisor or HYP mode, configures control registers and vectors, establishes kernel and optional abort stacks, and preserves boot arguments.
src/arch/arm/64/head.S:_start:On AArch64, masks interrupts, configures SCTLR_EL1 or SCTLR_EL2, selects the kernel stack, and, with SMP, consumes the loader-provided logical CPU index from TPIDR_EL1. Both architecture entries call arm_errata before init_kernel.
src/arch/arm/machine/errata.c:arm_errata:Applies configured CPU workarounds; CONFIG_ARM_ERRATA_773022 enables the affected Cortex-A15 loop-buffer workaround.
src/arch/arm/kernel/boot.c:init_kernel:Receives the loader arguments. Without SMP, calls try_init_kernel; with SMP, CPU 0 calls try_init_kernel while other CPUs call try_init_kernel_secondary_core.
src/arch/arm/kernel/boot.c:try_init_kernel_secondary_core:If SMP is enabled, secondary CPUs initially spin on node_boot_lock while CPU 0 constructs shared kernel state; their continuation occurs when release_secondary_cpus opens this gate.
src/arch/arm/kernel/boot.c:try_init_kernel:On the primary CPU, derives user virtual bounds by subtracting pv_offset from physical bounds; places the IPC buffer after the image, fixed BootInfo after the IPC buffer, and extra BootInfo after fixed BootInfo. Calls map_kernel_window.
src/arch/arm/64/kernel/vspace.c:map_kernel_window:On AArch64, links the kernel translation hierarchy, builds the physical-memory window, maps the kernel ELF image, links the device-window page table, and maps kernel devices.
src/arch/arm/64/kernel/vspace.c:map_kernel_physical_window:On AArch64, constructs the kernel's direct mapping of the configured physical-memory window.
src/arch/arm/64/kernel/vspace.c:map_kernel_elf_image:On AArch64, maps the kernel image at its linked virtual addresses using the configured mapping layout.
src/arch/arm/32/kernel/vspace.c:map_kernel_window:AArch32 alternative. Constructs ordinary or HYP kernel translation tables, maps the kernel memory window and exception vectors, and calls map_kernel_devices.
src/arch/arm/machine/hardware.c:map_kernel_devices:Maps MMIO frames described by generated kernel-device tables with kernel-only, non-executable device attributes; reserves kernel-owned device regions.
src/kernel/boot.c:reserve_region:Records reserved physical ranges in sorted order and merges adjacent ranges, preventing later distribution of those ranges as device untypeds.
src/arch/arm/kernel/boot.c:init_cpu:After map_kernel_window returns, initializes this CPU. On AArch64 HYP builds, first checks the loader's TCR_EL2 configuration; then calls activate_kernel_vspace.
src/arch/arm/64/kernel/vspace.c:activate_kernel_vspace:On AArch64, performs cache maintenance, installs seL4's kernel translation root and an empty user root, invalidates local translations, and requests the configured kernel TLB lock.
src/arch/arm/32/kernel/vspace.c:activate_kernel_vspace:AArch32 alternative. Performs cache maintenance and installs the ordinary kernel page directory or HYP translation root; the HYP implementation also initializes memory attributes and stage-2 translation controls.
src/arch/arm/kernel/boot.c:init_cpu:After activating kernel mappings, checks AArch64 non-HYP 16-bit ASID support, initializes optional hardware debugging, records the exception-entry kernel stack, installs AArch64 exception vectors, and initializes the local interrupt controller.
src/arch/arm/machine/gic_v2.c:cpu_initLocalIRQController:If the selected controller is GICv2, clears this CPU's active-IRQ bookkeeping and initializes its CPU interface.
src/arch/arm/machine/gic_v3.c:cpu_initLocalIRQController:GICv3 alternative. Records this CPU's MPIDR, clears active-IRQ bookkeeping, initializes its redistributor, and configures the system-register CPU interface.
src/arch/arm/object/vcpu.c:vcpu_boot_init:If HYP support is enabled, initializes architectural virtualization controls, determines supported virtual interrupt list registers, disables guest execution state, and clears the current-VCPU bookkeeping.
src/arch/arm/kernel/boot.c:init_cpu:Continues by probing FP/SIMD hardware, initially disabling it, and initializing configured FPU support. Initializes optional benchmark counters, configures permitted user access to architectural features, and calls initTimer.
src/drivers/timer/generic_timer.c:initTimer:If the selected platform uses this generic-timer implementation, delegates to initGenericTimer; other platforms provide their own initTimer implementation.
src/drivers/timer/generic_timer.c:initGenericTimer:Checks the configured counter frequency in debug builds, initializes periodic-tick or MCS deadline state, and enables the selected architectural timer.
src/arch/arm/kernel/boot.c:init_plat:After init_cpu succeeds, initializes shared platform hardware by calling initIRQController, initL2Cache, and, if configured, plat_smmu_init.
src/arch/arm/machine/gic_v2.c:initIRQController:For GICv2, validates IRQ bookkeeping assumptions and calls dist_init to initialize the shared interrupt distributor.
src/arch/arm/machine/gic_v3.c:initIRQController:GICv3 alternative. Calls dist_init to initialize the shared interrupt distributor.
src/arch/arm/kernel/boot.c:try_init_kernel:After platform initialization, checks any DTB for physical-address overflow and accessibility, reserves its range, and includes its header and payload in the extra-BootInfo size.
src/kernel/boot.c:calculate_extra_bi_size_bits:Returns zero for absent extra BootInfo; otherwise computes a page-sized or larger power-of-two allocation sufficient for the extra data.
src/arch/arm/kernel/boot.c:try_init_kernel:Computes the complete initial-thread virtual range, including IPC buffer and BootInfo, rejects ranges reaching USER_TOP, and calls arch_init_freemem.
src/arch/arm/kernel/boot.c:arch_init_freemem:Excludes the kernel image, DTB, root-task image, and applicable architecture-mode reservations from bootstrap allocation; passes generated available-RAM ranges to init_freemem.
src/kernel/boot.c:init_freemem:Validates available and reserved memory, restricts available RAM to the accessible kernel window, subtracts reserved ranges, and records remaining free ranges. Finds a suitably aligned contiguous region for the root task's initial objects.
src/kernel/boot.c:calculate_rootserver_size:Computes storage for the root CNode, TCB, IPC buffer, BootInfo, ASID pool, VSpace, subordinate paging structures, optional extra BootInfo, and optional MCS scheduling context.
src/kernel/boot.c:rootserver_max_size_bits:Computes the alignment needed by the largest root CNode, VSpace, or extra-BootInfo allocation.
src/kernel/boot.c:create_rootserver_objects:Partitions the chosen contiguous region into rootserver object storage; orders allocations to preserve alignment and records the paging-object allocation range.
src/kernel/boot.c:maybe_alloc_extra_bi:When the allocation order reaches the required alignment, allocates extra-BootInfo storage if it has not already been allocated.
src/kernel/boot.c:alloc_rootserver_obj:Allocates aligned object storage from the bootstrap region, advances its allocation pointer, checks bounds, and zeroes the allocated memory.
src/kernel/boot.c:create_root_cnode:After memory setup returns, constructs the root CNode capability and installs a self-reference at seL4_CapInitThreadCNode.
src/kernel/boot.c:write_slot:Writes a capability into its destination slot and initializes capability-derivation metadata; reused throughout creation of the initial environment.
src/kernel/boot.c:create_domain_cap:Installs the domain-control capability into the root CNode.
src/arch/arm/kernel/boot.c:init_irqs:Initializes IRQ software states, assigns the kernel timer and optional SMP IPIs, reserves configured kernel-owned interrupts, and installs seL4_CapIRQControl.
src/arch/arm/kernel/boot.c:init_smmu:If CONFIG_ARM_SMMU is enabled, initializes the platform SMMU and installs SID-control and context-bank-control capabilities.
src/arch/arm/kernel/boot.c:init_smc:If CONFIG_ALLOW_SMC_CALLS is enabled, installs the root task's SMC capability.
src/kernel/boot.c:populate_bi_frame:Clears fixed and optional extra BootInfo storage, records node information, IPC-buffer address, CNode size, initial domain, and extra length; initializes dynamic capability allocation after the fixed slots.
src/arch/arm/kernel/boot.c:try_init_kernel:Copies any DTB into extra BootInfo with an FDT header. For CONFIG_TK1_SMMU, calls create_iospace_caps and records its returned slot range; otherwise records an empty I/O-space range.
src/arch/arm/64/kernel/vspace.c:create_it_address_space:On AArch64, creates the initial VSpace capability and subordinate PUD, PD, and PT objects needed to cover the initial virtual range. The configured stage-2 starting level determines whether PUD allocation is needed.
src/arch/arm/32/kernel/vspace.c:create_it_address_space:AArch32 alternative. Copies applicable global mappings, creates the initial page-directory capability, and creates page tables covering the initial virtual range. Both architecture implementations record paging-capability slots in BootInfo.
include/kernel/boot.h:it_alloc_paging:During address-space construction, supplies each paging object from the previously allocated rootserver paging range and checks that the range is not exhausted.
src/kernel/boot.c:provide_cap:During paging and subsequent frame/untyped creation, installs each dynamic capability into the next available root-CNode slot; reports failure if the CNode is full.
src/kernel/boot.c:create_bi_frame_cap:After address-space construction, creates and maps the fixed BootInfo frame and installs its capability at seL4_CapBootInfoFrame.
src/arch/arm/64/kernel/vspace.c:create_mapped_it_frame_cap:On AArch64, constructs a frame capability with the initial ASID and virtual address, then installs its mapping; reused for BootInfo, IPC-buffer, and image frames.
src/arch/arm/32/kernel/vspace.c:create_mapped_it_frame_cap:AArch32 alternative. Constructs the appropriate frame capability and installs it in the initial address space.
src/kernel/boot.c:create_frames_of_region:If extra BootInfo exists, maps each backing page and supplies its frame capability. The caller records the returned capability range in BootInfo.extraBIPages.
src/kernel/boot.c:init_sched_control:If MCS is enabled, creates one scheduler-control capability per configured CPU and records their slot range in BootInfo.
src/kernel/boot.c:create_ipcbuf_frame_cap:Clears the IPC-buffer page, maps it into the root task, and installs its fixed-slot capability.
src/kernel/boot.c:create_frames_of_region:Called again for the loaded root-task image. Maps its existing physical pages at virtual addresses derived from pv_offset and supplies frame capabilities; the caller records BootInfo.userImageFrames.
src/kernel/boot.c:create_it_asid_pool:Constructs and installs the initial ASID-pool capability and the global ASID-control capability.
src/arch/arm/64/kernel/vspace.c:write_it_asid_pool:On AArch64, associates IT_ASID with the initial VSpace and registers its ASID pool globally; HYP builds initially leave hardware-VMID assignment invalid.
src/arch/arm/32/kernel/vspace.c:write_it_asid_pool:AArch32 alternative. Associates IT_ASID with the initial page directory and registers its pool in the global ASID table.
src/kernel/boot.c:create_idle_thread:Initializes an idle TCB for every configured CPU, records its CPU affinity where applicable, and attaches idle scheduling contexts in MCS builds.
src/kernel/thread.c:configureIdleThread:Marks the idle thread's FPU disabled, invokes architecture-specific context setup, and sets ThreadState_IdleThreadState.
src/arch/arm/64/kernel/thread.c:Arch_configureIdleThread:On AArch64, sets the idle thread's saved PC to idle_thread and its saved status to privileged EL1 or EL2 execution.
src/arch/arm/32/kernel/thread.c:Arch_configureIdleThread:AArch32 alternative. Sets the idle thread's saved PC to idle_thread and its saved CPSR to the configured privileged idle mode.
src/arch/arm/kernel/boot.c:try_init_kernel:After idle-thread creation, performs L1 cache maintenance so preceding page-table writes are visible before scheduling the initial thread, then calls create_initial_thread.
src/kernel/boot.c:create_initial_thread:Initializes the root TCB, derives its IPC-buffer capability, installs CSpace/VSpace/buffer capabilities into TCB slots, and records the IPC-buffer virtual address.
include/arch/arm/arch/64/mode/machine/registerset.h:Arch_initContext:On AArch64, initializes the root thread's saved status for EL0 execution and initializes optional breakpoint context.
include/arch/arm/arch/32/mode/machine/registerset.h:Arch_initContext:AArch32 alternative. Initializes the saved CPSR for user mode and initializes optional breakpoint context.
src/kernel/boot.c:create_initial_thread:Sets x0 or r0 to the BootInfo virtual address and sets the saved PC to the loader-provided root-image entry. Assigns maximum priority and control priority, domain 0, and Running state; installs the TCB capability and optional MCS scheduling-context capability.
src/kernel/boot.c:init_core_state:Sets this CPU's current thread to its idle thread and scheduler action to the newly created root thread. Initializes domain scheduling and configured FPU, debugging, and MCS per-core state.
src/kernel/boot.c:create_untypeds:Creates device untypeds for unreserved physical-address gaps, normal untypeds for reusable kernel boot memory, and normal untypeds for remaining free RAM; records their capability range in BootInfo.
src/kernel/boot.c:create_untypeds_for_region:Splits each memory region into supported aligned power-of-two chunks and supplies an untyped capability for every sufficiently large chunk.
src/kernel/boot.c:provide_untyped_cap:Validates the chunk, creates its untyped capability, and records physical address, size, and device status in BootInfo.untypedList.
src/kernel/boot.c:bi_finalise:After untyped creation, records the root CNode's remaining empty slots and checks whether all predicted paging objects were consumed.
src/arch/arm/kernel/boot.c:try_init_kernel:Records an empty shared-frame range, performs final cache and local-TLB maintenance plus HYP-TLB maintenance if configured, and sets ksNumCPUs to one. If SMP is enabled, initializes the kernel lock and calls release_secondary_cpus.
src/arch/arm/kernel/boot.c:release_secondary_cpus:If SMP is enabled, opens node_boot_lock, performs required AArch32 cache maintenance, and waits until every configured secondary CPU has completed initialization.
src/arch/arm/kernel/boot.c:try_init_kernel_secondary_core:Each released secondary calls init_cpu, configures local interrupt states for IPIs, timer, and optional virtualization interrupts, enters kernel-lock synchronization, optionally checks clock synchronization, increments ksNumCPUs, and calls init_core_state.
src/kernel/boot.c:init_core_state:On each secondary, receives SchedulerAction_ResumeCurrentThread, leaving that CPU's idle thread current; the root-task candidate belongs to CPU 0.
src/arch/arm/kernel/boot.c:try_init_kernel:After secondary initialization, the primary acquires the kernel lock where applicable and returns success. The boot-complete message precedes actual userspace entry.
src/arch/arm/kernel/boot.c:init_kernel:After successful initialization, updates MCS time accounting if enabled, calls schedule, then activateThread. If initialization reported failure, calls fail instead.
src/kernel/thread.c:schedule:On CPU 0, processes the explicit root-thread candidate installed by init_core_state and selects it through switchToThread; secondary CPUs initially resume their idle threads. MCS builds also update scheduling-context and timer-deadline state.
src/kernel/thread.c:switchToThread:Calls Arch_switchToThread, applies configured lazy-FPU handling, removes the selected thread from ready-queue bookkeeping, and assigns it to ksCurThread.
src/arch/arm/64/kernel/thread.c:Arch_switchToThread:On AArch64, switches configured VCPU state and invokes setVMRoot for the root task.
src/arch/arm/32/kernel/thread.c:Arch_switchToThread:AArch32 alternative. Switches configured VCPU state, invokes setVMRoot, and clears the exclusive monitor.
src/arch/arm/64/kernel/vspace.c:setVMRoot:On AArch64, reads the TCB's VSpace capability, verifies its ASID association, and invokes armv_contextSwitch to install it.
include/arch/arm/armv/armv8-a/64/armv/context_switch.h:armv_contextSwitch:On AArch64, installs the user translation root and ASID; HYP builds first obtain the corresponding hardware VMID.
src/arch/arm/32/kernel/vspace.c:setVMRoot:AArch32 alternative. Validates the TCB's page-directory capability and ASID association before invoking armv_contextSwitch.
include/arch/arm/armv/armv7-a/armv/context_switch.h:armv_contextSwitch:On AArch32, obtains the hardware ASID and delegates to armv_contextSwitch_HWASID to install the address space with the required translation-register ordering.
src/kernel/thread.c:activateThread:Returns immediately for the root task's already-Running state. Other states can require restart-PC adjustment or architecture-specific idle activation.
src/arch/arm/64/head.S:_start:On AArch64, init_kernel returns to this assembly entry, which branches to restore_user_context rather than calling the root image as a C function.
src/arch/arm/32/head.S:_start:AArch32 alternative. After init_kernel returns, branches to the architecture's restore_user_context implementation.
src/arch/arm/64/c_traps.c:restore_user_context:On AArch64, runs exit hooks, restores thread-ID and optional debug state, releases the kernel lock, loads saved registers, SP_EL0, exception-return PC and status, and executes eret. CPU 0 enters the root image at v_entry in EL0 with the BootInfo pointer in x0; the root image's own startup code lies outside this checkout.
src/arch/arm/32/c_traps.c:restore_user_context:AArch32 alternative. Runs exit hooks, restores thread-ID and optional debug state, releases the kernel lock, and restores the user context. Uses rfeia for ordinary kernels or eret for HYP kernels; CPU 0 enters the root image at v_entry in user mode with the BootInfo pointer in r0.
